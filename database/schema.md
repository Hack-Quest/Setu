# 🗄️ Setu Database Schema (PostgreSQL / Supabase)

This document outlines the exact data structures expected by the database modules. All data is stored in a relational PostgreSQL database.

---

## 1. Needs / Reports (`needs_reports` table)
Stores distress reports submitted to the platform.

| Column | Type | Description |
| :--- | :--- | :--- |
| `id` | VARCHAR(100) PRIMARY KEY | Unique ID of the need |
| `reporter_name` | VARCHAR(100) | Name of the person reporting |
| `reporter_phone` | VARCHAR(20) | Contact number |
| `location_text` | TEXT | Raw address entered |
| `description` | TEXT | Description of emergency |
| `lat` | DOUBLE PRECISION | Geocoded latitude |
| `lng` | DOUBLE PRECISION | Geocoded longitude |
| `severity` | VARCHAR(50) | `critical`, `high`, `medium`, `low` (Generated by AI) |
| `category` | VARCHAR(100) | e.g. `medical`, `rescue`, `food`, `shelter` |
| `status` | VARCHAR(50) | `open`, `assigned`, `resolved` |
| `timestamp` | TIMESTAMPTZ | Creation timestamp |
| `updated_at` | TIMESTAMPTZ | Last updated timestamp |
| `trust_score` | INTEGER | Platform confidence score (0-100) |
| `summary_en` | TEXT | English summary generated by LLM |
| `summary_local` | TEXT | Localized summary generated by LLM |
| `disaster_type` | VARCHAR(100) | Identified disaster (e.g. `flood`, `accident`) |
| `help_needed` | VARCHAR(100) | Main type of assistance needed |

---

## 2. Volunteers (`volunteers` table)
Registered volunteers on the platform.

| Column | Type | Description |
| :--- | :--- | :--- |
| `id` | VARCHAR(100) PRIMARY KEY | Unique ID (matches the auth record) |
| `name` | VARCHAR(100) | Volunteer name |
| `phone` | VARCHAR(20) | Contact number |
| `skills` | TEXT[] | Array of skills (e.g. `['medical', 'rescue']`) |
| `location` | VARCHAR(200) | base location name |
| `lat` | DOUBLE PRECISION | Base latitude |
| `lng` | DOUBLE PRECISION | Base longitude |
| `ngo_id` | VARCHAR(100) | Associated NGO ID (null for Tier 2) |
| `available` | BOOLEAN | `true` if free, `false` if deployed |
| `registered_at` | TIMESTAMPTZ | Registration timestamp |
| `assignments_count` | INTEGER | Count of active assignments |

---

## 3. Volunteers Auth (`volunteers_auth` table)
Credentials for volunteer standard portal logins.

| Column | Type | Description |
| :--- | :--- | :--- |
| `id` | VARCHAR(100) PRIMARY KEY | Unique ID referencing volunteers table |
| `email` | VARCHAR(150) UNIQUE | Login email |
| `password_hash` | VARCHAR(255) | Hashed password |

---

## 4. NGOs (`ngos` table)
Registered NGOs with coverage radii.

| Column | Type | Description |
| :--- | :--- | :--- |
| `id` | VARCHAR(100) PRIMARY KEY | Unique NGO ID |
| `ngo_name` | VARCHAR(150) | Organization name |
| `reg_number` | VARCHAR(100) UNIQUE | State registration number |
| `location` | VARCHAR(200) | Base location address |
| `lat` | DOUBLE PRECISION | Center latitude of operations |
| `lng` | DOUBLE PRECISION | Center longitude of operations |
| `radius` | DOUBLE PRECISION | Coverage radius (in km) |
| `verified` | BOOLEAN | Trust status verification flag |
| `registered_at` | TIMESTAMPTZ | Registration timestamp |
| `verified_at` | TIMESTAMPTZ | Verification timestamp |

---

## 5. Assignments (`assignments` table)
Tracks dispatches of volunteers to reported needs.

| Column | Type | Description |
| :--- | :--- | :--- |
| `id` | VARCHAR(100) PRIMARY KEY | Unique assignment ID |
| `need_id` | VARCHAR(100) | Need ID |
| `volunteer_id` | VARCHAR(100) | Volunteer ID |
| `assigned_at` | TIMESTAMPTZ | Dispatch timestamp |
| `resolved_at` | TIMESTAMPTZ | Resolution timestamp (null if active) |

---

## 6. OTPs (`otps` table)
Single-use OTP verification codes.

| Column | Type | Description |
| :--- | :--- | :--- |
| `email` | VARCHAR(150) PRIMARY KEY | Recipient email |
| `otp` | VARCHAR(10) | 6-digit OTP code |
| `expires_at` | TIMESTAMPTZ | Code expiration timestamp |
| `created_at` | TIMESTAMPTZ | Code creation timestamp |
